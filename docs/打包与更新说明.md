# 打包与更新说明

## 打包 exe

```powershell
.venv/Scripts/python.exe -m PyInstaller shiguang.spec --noconfirm
```

产物：`dist/拾光/拾光.exe`（onedir 模式，整个 `dist/拾光/` 目录即为可分发应用，
可压缩为 zip 分发，用户解压后运行 `拾光.exe`）。

调试打包问题：将 `shiguang.spec` 中 `console=False` 临时改为 `True`，
重打包后在终端运行 exe 可直接看到报错堆栈。

## 数据与 exe 的关系（为什么更新不会丢数据）

- **exe 里只有代码，没有数据**。数据库固定存放在用户目录：
  `%LOCALAPPDATA%\Shiguang\Shiguang\shiguang.db`
  （由 `platformdirs` 解析；冻结态下 `config.get_db_path()` 强制走此路径，
  见 `src/shiguang/config.py`）。
- 更新 = 替换 `dist/拾光/` 目录（或仅替换其中的 exe 与 `_internal`），
  数据库文件原封不动，数据完整保留。

## 以后新增表/改表结构怎么办

项目已内置 Alembic 迁移机制，**启动时自动升级老数据库**：

1. 开发新功能时新增迁移脚本：
   ```powershell
   .venv/Scripts/python.exe -m alembic revision -m "add_xxx_table"
   ```
   在生成的 `src/shiguang/db/migrations/versions/0003_xxx.py` 中编写
   `upgrade()`（`op.create_table(...)` / `op.add_column(...)`）。
2. 重新打包。迁移脚本会作为数据文件打进 exe（见 `shiguang.spec` 的 datas）。
3. 用户用新 exe 首次启动时，`migration_runner.upgrade_head()` 检测到
   数据库版本落后，自动执行新迁移：新表会被创建到**现有数据库**中，
   旧数据全部保留。

注意事项：

- 迁移脚本只做**增量、可累加**的修改（新表、新列给默认值）；如需删列/改类型，
  在迁移里先复制数据再变更（SQLite 用 `op.batch_alter_table`）。
- 每次发布前在开发库上验证：`upgrade_head()` 对老库重复执行是幂等的。
- 建议后续版本在设置页加"备份数据库"入口（复制该 db 文件即可），进一步兜底。
