## 1. 产品概述

### 1.1 产品定位

**拾光** 是一款个人事务管理与自我复盘工具，覆盖「目标规划 → 日常代办 → 习惯养成 → 每日复盘 → 数据统计」的完整闭环。

### 1.2 核心理念

**以质量取胜，而不是以量取胜。**

与普通代办工具不同，拾光在代办的创建与完成两个关键节点都设计了"留痕"机制：

- **创建时**：要求填写「代办流程/完成标准」，事前明确质量要求；
- **完成时（归档）**：要求填写用时、质量评分、总结，事后沉淀经验。

### 1.3 核心闭环

```
目标计划（蓝图）
   ↓ 拆解/关联
日常代办（行动）  ←→  习惯养成（每日重复的特殊行动）
   ↓ 归档留痕
每日日记（复盘，自动汇总当日完成情况）
   ↓ 数据沉淀
数据统计（反馈，驱动下一阶段目标调整）
```

## 2. 开放问题讨论与结论（已全部确认）

### 2.1 目标计划 与 日常代办是否合并？

**结论：数据模型统一，表现层（UI）分模块。**

| 维度 | 处理方式 | 理由 |
| --- | --- | --- |
| 数据模型 | 统一为「任务（Task）」实体，用 `周期` 字段区分：日 / 周 / 月 / 年 | 两者字段、归档流程几乎一致，重复建模浪费 |
| 表现层 | 保留「日常代办」「目标计划」两个独立入口 | 用户心智不同：代办是"今天做什么"，目标是"这段时间要成为什么" |
| 目标特有属性 | 进度（由关联代办/子目标的完成情况自动计算）、被关联关系 | 目标是蓝图，天然需要聚合视图 |

关联规则（自洽的树状/网状结构）：

- 日代办 → 可关联 周 / 月 / 年目标
- 周目标 → 可关联 月 / 年目标
- 月目标 → 可关联 年目标
- 不允许反向关联（年目标不能关联日代办），避免循环依赖

### 2.2 习惯养成 与 每日重复代办是否区分？

**结论：习惯是独立模块，但数据模型复用任务实体，打卡记录独立存储。**

习惯的本质 = 每日重复代办 + 极简打卡 + 连续坚持统计。与日常代办的关键差异：

| 维度 | 日常代办 | 习惯养成 |
| --- | --- | --- |
| 完成动作 | 归档（填用时/评分/总结） | 一键打卡（轻量，可选备注） |
| 激励点 | 单次完成质量 | 连续坚持天数（streak） |
| 核心统计 | 完成率、平均评分、用时 | 连续天数、月度打卡率 |
| 心理模型 | "把这件事做好" | "今天别断" |

> 设计考量：若习惯也强制走完整归档流程，每天写评分和总结会迅速耗尽用户耐心。习惯贵在坚持，交互必须轻。

### 2.3 每日日记是否自动带出当日内容？

**结论：要。创建日记时自动汇总当日数据，以只读引用块插入。**

自动带出的内容：

- 今日完成（归档）的代办列表：名称 + 质量评分
- 今日习惯打卡情况
- 今日关联目标的进度变化

结构：`[自动汇总区（只读）] + [自由书写区]`。复盘成本趋近于零，这是产品闭环的点睛之笔。

### 2.4 数据统计范围

**结论：分期实现，MVP 先做最有成就感的部分。**

- MVP：代办完成率、代办/日记热力图（GitHub 风格）
- v1.1：质量评分趋势（折线）、用时分布（柱状）
- v1.2：习惯连续天数榜、目标完成进度总览、周期复盘报告

## 3. 信息架构

```
拾光
├── 今日（首页）
│   ├── 今日代办列表
│   ├── 今日习惯打卡
│   └── 快速创建入口
├── 代办
│   ├── 列表（按日期/状态筛选）
│   ├── 创建/编辑代办
│   └── 归档（完成弹窗）
├── 目标
│   ├── 周目标 / 月目标 / 年目标（Tab 切换）
│   ├── 目标详情（含关联代办、进度）
│   └── 创建/归档目标
├── 习惯
│   ├── 习惯列表（含连续天数）
│   └── 打卡日历
├── 日记
│   ├── 日记列表 / 日历视图
│   └── 编辑（自动汇总 + 自由书写）
└── 统计
    ├── 热力图（代办 / 日记）
    └── 图表（完成率 / 评分 / 用时）
```

## 4. 领域模型（数据实体草案）

### 4.1 Task（任务：代办 / 目标 统一实体）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 主键 |
| name | string | 名称 |
| kind | enum: `todo` / `goal` | 代办 或 目标 |
| period | enum: `day` / `week` / `month` / `year` | 周期。代办固定为 day；目标为 week/month/year |
| repeat | enum: `none` / `daily` / `weekly` / `monthly` | 重复规则（仅代办） |
| date | date | 计划日期（不重复时为具体日期） |
| delayPolicy | enum: `default` / `never` / `auto` | 延期策略：默认(不延期) / 不延期 / 自动延期 |
| relatedTaskIds | string[] | 关联的目标（代办→目标；低周期目标→高周期目标） |
| description | text | 描述 |
| standard | text | 代办流程/完成标准 |
| status | enum: `pending` / `archived` | 待办 / 已归档 |
| createdAt / updatedAt | datetime | 时间戳 |

> 注：`repeat ≠ none` 的代办作为"模板"存在，按规则生成每日/每周/每月的具体实例；实例归档互不影响。

### 4.2 ArchiveRecord（归档记录）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 主键 |
| taskId | string | 关联任务（归档时自动带出名称/描述/完成标准） |
| duration | number | 代办用时（分钟） |
| score | number | 质量评分（如 1–5 或 1–10，待决策） |
| summary | text | 总结 |
| archivedAt | datetime | 归档时间 |

### 4.3 Habit（习惯，轻量实体或 Task 的扩展标记）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 主键 |
| name | string | 习惯名称 |
| description | text | 描述（可选） |
| status | enum: `active` / `archived` | 进行中 / 已结束 |

### 4.4 HabitCheckin（习惯打卡记录）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 主键 |
| habitId | string | 关联习惯 |
| date | date | 打卡日期（同一天唯一） |
| note | text | 备注（可选） |

> 连续天数（streak）、月度打卡率由打卡记录计算得出，不冗余存储。

### 4.5 DiaryEntry（日记）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 主键 |
| date | date | 日记日期（每天一篇） |
| autoSummary | json | 自动汇总快照（当日代办/习惯/目标进度，只读） |
| content | text | 自由书写内容 |
| createdAt / updatedAt | datetime | 时间戳 |

## 5. 模块详细设计

### 5.1 日常代办（核心模块）

#### 创建代办

| 表单项 | 说明 |
| --- | --- |
| 名称 | 必填 |
| 重复 | 不重复 / 每日 / 每周 / 每月 |
| 日期选择 | **随重复选项联动变化**：不重复→选具体日期；每日→选日期范围（开始日期必填，结束日期可选，留空表示长期）；每周→选星期几；每月→选每月几号 |
| 延期 | 默认(不延期) / 不延期 / 自动延期（过期未完成自动顺延到下一日） |
| 目标 | 关联周/月/年目标（可多选，可空） |
| 描述 | 代办细节 |
| 代办流程/完成标准 | **必填**。完成质量要求，事前提示（表单设计详见 UI 设计文档 §4.3） |

#### 归档代办（完成弹窗）

| 表单项 | 说明 |
| --- | --- |
| 名称 / 描述 / 完成标准 | 自动带出，只读，帮助用户对标准自检 |
| 代办用时 | 实际完成用时（必填） |
| 质量评分 | 主观评分，1–5 星（必填） |
| 总结 | **可选**（UI 设计文档已调整为可选，降低归档摩擦）。留痕沉淀，如阅读代办可写读后感 |

#### 列表与状态

- 默认视图：今日代办（含昨日逾期未处理项，置顶标红）
- 筛选：按日期 / 状态（待办、已归档、逾期）
- 逾期处理：`auto` → 自动顺延；`never/default` → 保持逾期状态，用户手动处理

### 5.2 目标计划

- 按 周 / 月 / 年 三个 Tab 管理
- 创建/编辑/归档流程与代办基本一致（复用表单组件）
- **目标详情页**核心展示：
  - 关联的代办与低周期目标列表及其完成状态
  - 进度条：由关联项完成率自动计算（如：关联 5 个代办，归档 3 个 → 60%）
- 归档目标时同样走归档弹窗（用时改为可选，评分与总结必填）

### 5.3 习惯养成

- 习惯列表：卡片式，展示名称 + 当前连续天数 + 今日是否已打卡
- 打卡动作：一键完成，可展开写备注
- 习惯详情：月度打卡日历视图 + 历史最长连续天数
- 习惯不设截止日期，可手动"结束"（归档）

### 5.4 每日日记

- 创建入口：日记 Tab / 今日首页；每天一篇，重复进入则编辑
- 编辑器结构：
  - **自动汇总区**（只读）：今日归档代办（名称+评分）、习惯打卡、目标进度变化
  - **自由书写区**：富文本或 Markdown（待决策）
- 历史浏览：列表 + 日历双视图，日历上有日记的日期高亮

### 5.5 数据统计

| 迭代 | 图表 | 数据源 |
| --- | --- | --- |
| MVP | 代办完成热力图（GitHub 风格，按天着色） | 归档记录 |
| MVP | 日记记录热力图 | 日记 |
| MVP | 代办完成率（按周/月，柱状图） | 任务 + 归档记录 |
| v1.1 | 质量评分趋势（折线图） | 归档记录.score |
| v1.1 | 用时分布（柱状图） | 归档记录.duration |
| v1.2 | 习惯连续天数榜 / 月度打卡率（扇形图） | 打卡记录 |
| v1.2 | 目标完成进度总览 | 目标 + 关联代办 |

## 6. 关键业务规则

1. **重复代办实例生成**：每日启动应用（或定时任务）检查重复模板，为当天生成待办实例；实例独立归档，删除模板不影响历史实例。
2. **自动延期**：当天结束仍未完成且 `delayPolicy = auto` 的代办，日期顺延至次日，并记录延期次数（统计用）。
3. **目标进度计算**：`进度 = 已归档关联项数 / 全部关联项数`，实时计算，不冗余存储。
4. **归档不可逆（MVP）**：归档后进入只读历史；如需“反悔”，v1.x 再考虑撤销归档功能。
   - 补充（v0.3）：归档信息中「总结」为可选项，「用时」「评分」必填。
5. **日记自动汇总快照**：写入时生成快照存 `autoSummary`，之后修改代办记录不回溯改日记（保留当时语境）。
