# T01 HTML 界面原型 Demo

- **所属阶段**：一 · 界面原型
- **前置任务**：无
- **类型**：design

## 任务目标

按《UI 设计文档》实施代办模块的 HTML 静态原型，覆盖代办模块全部页面与交互状态。原型以 UI 设计文档为唯一依据，全部使用写死的假数据。

## 任务内容

1. 按 UI 设计文档 §9.1 建立 `prototype/` 文件结构（`tokens.css` 必须使用 §2 的设计令牌原值）
2. 按 §9.4 优先级实施 **Step 1–5**（本模块范围；Step 6/7 属于后续模块）：
   - Step 1：全局框架（64px 图标导航栏 + 页面容器 + 令牌系统）——导航含今日/代办/日记/统计，日记与统计仅占位
   - Step 2：今日首页（§4.1：顶部功能区含状态表情、DateBar、概览卡片×2、今日代办列表、通栏"添加今日代办"按钮、空状态）
   - Step 3：代办列表页（§4.2：Pill 筛选标签、日期筛选器、列表、三种状态卡片）
   - Step 4：创建代办弹窗（§4.3：520px、表单、重复联动展开、验证样式）
   - Step 5：归档弹窗（§4.4：580px、只读任务信息卡、评分组件、绿色确认按钮——仪式感最重要）
3. `mock-data.js` 假数据需覆盖：普通今日代办、带完成标准的代办、逾期代办（含已延期次数）、每日重复代办、已归档代办（带评分/用时/总结）
4. 用原生 JS 演示关键交互：导航切换、DateBar 日期切换、Tab 筛选、弹窗打开/关闭、评分星星 hover/选中、重复模式联动展开

## 涉及文件

- `prototype/`（index.html、css/、js/、assets/）

## 验收标准

- [ ] Step 1–5 全部完成，浏览器打开可直接查看与交互演示
- [ ] 样式值全部取自 tokens.css（与 UI 设计文档 §2 一致），无随手写的色值/尺寸
- [ ] 覆盖 §6.1 中与代办相关的空状态（今日无代办、筛选为空、归档为空）
- [ ] **用户亲自评审通过后**本任务才算完成

## 备注

- 原型表达布局、配色、组件形态与关键交互状态，不追求像素完美，但令牌值必须准确。
- 用户确认后再进入 T02。
