# T02 原型走查与验收

- **所属阶段**：一 · 界面原型
- **前置任务**：T01（问题清单修复完毕，用户初步确认）
- **类型**：docs

## 任务目标

对照《UI 设计文档》逐组件走查 `prototype/` 实际产出，记录并修订差异，冻结阶段二的 UI 实现依据。

## 任务内容

1. 制作走查清单并逐项核对（`prototype/` vs UI 设计文档）：
   - 设计令牌：§2 色彩/字体/间距/圆角/阴影/过渡，抽查 `css/tokens.css` 与实际渲染
   - 全局框架：§3 窗口规格、导航栏（64px、选中竖线、Tooltip）
   - 模块一相关页面：§4.1 今日首页、§4.2 代办列表页
   - 弹窗：§4.3 创建弹窗、§4.4 归档弹窗
   - 组件：§5.1 TaskCard 三种状态变体、§5.2 DateBar、§5.3 RatingWidget
   - 空状态：§6.1 与代办相关的场景文案
   - 动效：§7 关键时长与缓动抽查
2. **顺带登记**（不深入走查，属后续模块）：日记页（§4.5）、统计页（§4.6）、目标/习惯页（§10）的覆盖情况与明显偏差，记入 REVIEW.md 附录，供模块二/三/四/五拆解任务时参考
3. 差异处理二选一：改原型对齐文档，或确有更好方案则先改 UI 设计文档（升版本号）再对齐原型
4. 走查结论写入 `prototype/REVIEW.md`（每项 ✅ / 差异描述 / 处理方式）

## 涉及文件

- `prototype/REVIEW.md`（新建）
- `prototype/`（可能的修订）
- `docs/UI设计文档.md`（可能的修订，需升版本号）

## 验收标准

- [ ] 模块一走查清单全部项有结论（✅ 或已修订）
- [ ] 后续模块页面覆盖情况已登记到 REVIEW.md 附录
- [ ] 用户确认原型可进入开发，T01/T02 同时关闭

## 备注

- 本任务完成后，阶段二 UI 任务以「UI 设计文档 + prototype/」为准。
