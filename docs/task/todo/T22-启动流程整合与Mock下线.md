# T22 启动流程整合与 Mock 下线

- **所属阶段**：四 · 数据层落地
- **前置任务**：T20
- **类型**：feat

## 任务目标

完成启动序列与跨天自动刷新，默认以真实服务运行，Mock 仅保留测试/演示用途。**代办模块收官任务。**

## 功能描述与流程

1. 启动序列：定位数据目录 → 数据库迁移到最新版本 → 执行一次逾期自动延期扫描 → 显示主窗口；启动耗时给出加载反馈。
   - 注意：**不再有"启动时补生成重复代办"的步骤**——重复代办在创建时已一次性展开，重启后自然各就其位。
2. 跨天自动刷新：应用运行期间每分钟检查一次日期，发现跨天后重新执行延期扫描，并通过统一变更信号通知全部页面刷新（UI 只订阅一个变更信号，UI 代码零改动）；窗口从休眠/最小化恢复激活时补做一次日期检查（覆盖系统休眠场景）。
3. `USE_MOCK` 默认切换为 `false`；Mock 实现保留。
4. 集成测试：模拟日期下启动序列端到端（逾期 auto 代办启动后被顺延且延期次数 +1）。
5. 全量回归：pytest 全过 + ruff 通过 + 手工 checklist：
   - 创建"每日"重复代办（开始昨天、结束明天）→ 重启应用 → 今天列表仍展示该代办（创建时已生成，不依赖启动补齐）
   - 逾期 auto 代办启动后顺延且延期次数 +1
   - 归档数据重启后持久
   - DateBar 圆点、概览卡片、状态表情与真实数据一致
6. 更新 `docs/task/task.md`：模块一全部标记 ✅。

## 验收标准

- [ ] 启动序列集成测试通过；跨天定时器单测通过
- [ ] 手工 checklist 四项全过
- [ ] 全量测试 + ruff 通过；task.md 模块一全部 ✅
