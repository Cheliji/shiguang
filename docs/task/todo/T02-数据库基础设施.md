# T02 数据库基础设施（引擎 / 会话 / 迁移）

- **所属阶段**：一 · 工程与数据基础
- **前置任务**：T01
- **类型**：feat

## 任务目标

建立 SQLite 连接、会话管理与 Alembic 迁移骨架，使应用能通过代码创建/升级数据库。**本任务不定义任何业务表。**

## 任务内容

1. `config.py`：用 `platformdirs` 解析数据目录（生产 `%APPDATA%/Shiguang`，开发模式用项目 `./data`），暴露 `get_db_path()`。
2. `db/session.py`：
   - `create_engine_for(path)`：开启 WAL 模式（`PRAGMA journal_mode=WAL`）
   - 会话工厂 `SessionLocal` 与上下文管理器 `session_scope()`（自动 commit/rollback/close）
3. `models/base.py`：SQLAlchemy 2.x 声明式 `Base`。
4. 接入 Alembic：`alembic.ini` 与 `db/migrations/`，连接串从 `config` 读取。
5. `db/migration_runner.py`：提供 `upgrade_head()`，供启动序列调用。
6. 单元测试：内存 SQLite 上验证 `session_scope` 提交与回滚行为。

## 涉及文件

- `src/shiguang/config.py`（新建）
- `src/shiguang/db/session.py`、`db/migration_runner.py`（新建）
- `src/shiguang/models/base.py`（新建）
- `alembic.ini`、`src/shiguang/db/migrations/`（新建）
- `tests/test_db_session.py`（新建）

## 验收标准

- [ ] 调用 `upgrade_head()` 后能在指定路径创建空的 `shiguang.db`
- [ ] 单元测试通过：session 提交后数据可见、异常时回滚
- [ ] 测试全部使用内存库，不产生真实文件

## 备注

- 不要在 `session.py` 模块 import 时就创建全局 engine（路径可能未就绪），用函数延迟创建。
