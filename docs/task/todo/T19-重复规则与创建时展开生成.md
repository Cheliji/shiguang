# T19 重复规则与创建时展开生成

- **所属阶段**：四 · 数据层落地
- **前置任务**：T21
- **类型**：feat

## 任务目标

实现重复代办的创建时展开：用户选择每日/每周/每月并给出开始、结束日期后，创建动作一次性生成区间内全部日期的独立代办记录。生成只发生在创建这一刻——没有模板、没有延迟生成，也不需要幂等机制。

## 功能描述与流程

1. 展开规则（开始日期与结束日期均含边界）：
   - **每日**：从开始日期到结束日期每天一条。例：2026-10-22 ~ 2026-11-01 → 11 条。
   - **每周**：从开始日期起每 7 天一条，不超过结束日期。例：2026-10-22 ~ 2026-11-01 → 10-22、10-29 共 2 条。
   - **每月**：从开始日期起每月同一日号一条，不超过结束日期。例：2026-10-22 ~ 2027-11-01 → 每月 22 日共 13 条。
2. 创建流程：表单校验通过 → 计算展开日期集合 → 同一事务内批量生成全部记录（每条拷贝表单字段、写入各自计划日期、保存创建时的重复规则、共享同一系列标识）→ 创建成功反馈包含生成条数。
3. 解除 T18 的过渡限制：重复周期不为"不重复"的创建请求不再被拒绝，走上述展开流程。

## 边界情况

- 结束日期早于开始日期 → 拒绝创建（表单层已拦截，服务层兜底校验）；
- 每月规则的日号在某月不存在（如 1 月 31 日起每月重复，2 月无 31 日；2 月 29 日遇平年）→ 跳过该月；
- 展开条数上限 400 条，超出拒绝创建并提示缩短日期范围；
- 首条恒为开始日期，展开结果不会为空；
- 生成后的记录相互独立：编辑/删除/归档只作用于单条，删除其中一条不影响同系列其余记录。

## 验收标准

- [ ] 单元测试全部通过：三种规则 + 上述示例的精确断言 + 跳过无日号月份 + 400 条上限 + 日期倒挂
- [ ] 真实库创建"每日"代办（开始今天、结束 3 天后）→ 今天起连续 4 天的列表各出现一条
- [ ] 归档重复系列中的一天，其余日期的记录不受影响

## 备注

- 展开日期计算是纯函数（不碰数据库），是全项目最需要测试覆盖的代码。
- 系列标识仅用于标识同批生成的记录，MVP 不提供系列级批量编辑/删除（v1.x 再议）。
