# T15 数据库基础设施（引擎 / 会话 / 迁移）

- **所属阶段**：四 · 数据层落地
- **前置任务**：T24
- **类型**：feat

## 任务目标

让应用具备本地持久化的基础能力：数据库文件定位、连接与会话管理、表结构版本化迁移。**本任务不建任何业务表、不改 UI。**

## 功能描述

1. 数据目录定位：生产环境数据库位于用户应用数据目录（`%APPDATA%/Shiguang/shiguang.db`）；开发环境使用项目根目录 `./data/shiguang-dev.db`；测试一律使用内存数据库，每个用例独立。
2. 连接与会话：数据库连接启用 WAL 模式；提供统一的"会话作用域"使用方式——正常结束自动提交，发生异常自动回滚并关闭连接。
3. 迁移机制：接入 Alembic 做表结构版本管理；提供"升级到最新版本"的能力，供应用启动时调用，用户无感升级。
4. `USE_MOCK` 开关沿用现状（默认 Mock），本任务不改动。

## 边界情况

- 数据目录不存在时能自动创建；
- 重复执行"升级到最新版本"是安全的（已是最新则什么都不做）；
- 会话中抛出异常时，已做的写入必须整体回滚，不留半截数据。

## 验收标准

- [ ] 调用升级能力后，开发目录下能创建空的 `shiguang-dev.db`
- [ ] 单元测试通过：会话正常提交后数据可见、异常时回滚；全部使用内存库

## 备注

- 不要在模块导入时创建全局连接，按需延迟创建。
