# 拾光 · 任务总览

> 本文档描述总体任务进度与任务执行规则。各任务的详细内容见同目录下按模块划分的任务文档。

## 总体策略：UI 先行，数据后置

开发顺序为「**界面原型（HTML demo）→ PySide6 UI 实现（接口 + Mock 数据）→ 数据层落地（替换 Mock）**」：

- 先做纯 HTML 静态原型，按《UI 设计文档》（docs/UI设计文档.md）实施并与用户走查确认；
- UI 实现阶段只依赖**服务接口 + 内存 Mock 数据**，不碰数据库，快速看到完整交互；
- 最后实现真实服务层与数据库，通过依赖注入无缝替换 Mock。

**原型现状（重要）**：`prototype/` 已由用户借助 AI 完成初版，覆盖**全部 7 个页面**（今日/代办/目标/习惯/日记/统计/设置）与 4 个弹窗（新建代办/归档/习惯详情/目标详情），超出模块一原定范围（Step 1–5）。影响：

- 模块一 T01 剩余工作仅为「修复用户反馈的小问题」（详见 T01 任务文档）；
- 后续模块（日记/统计/目标/习惯）拆解任务时，原型步骤可直接跳过或仅做对应页面的补充走查，从 UI 实现开始。

**UI 唯一依据**：`docs/UI设计文档.md`（设计令牌、页面线框、组件规格、动效、空状态）。任务文档中所有"§x.x"引用均指向该文档。

## 任务执行规则（重要）

1. **严格顺序执行**：任务按编号从小到大进行，前置任务未完成不得开始后续任务；任务已按"最小可验证功能"拆分，禁止自行合并任务。
2. **最小粒度**：每个任务只完成文档中描述的内容，**不实现后续任务的功能**（如 T10 只做基础字段表单，不做重复联动）。
3. **一任务一提交**：每个任务完成并满足验收标准后，立即创建一个 git commit（遵循 AGENT.md），提交信息格式：`类型(Txx): 描述`，如 `feat(T09): 今日首页`。
4. **验收驱动**：任务完成的标准 = 该任务文档「验收标准」一节全部通过。通过后回本文档更新状态为 ✅。
5. **设计一致**：原型与 UI 实现必须逐组件对照《UI 设计文档》，不自由发挥；实现中确需调整的，先改设计文档再改代码。
6. **文档同步**：实现过程中若与产品/技术/UI 任一设计文档产生偏差，先更新设计文档再写代码。
7. **测试要求**：阶段三（服务层/领域层）任务必须附带 pytest 单元测试；UI 任务至少手工走通验收标准，关键流程用 pytest-qt 冒烟。

## UI 制作要求（用户指定，全阶段生效）

1. **图标**：按钮/图标一律使用成熟开源矢量图标库（首选 Feather Icons / Lucide），下载 SVG 存入 `resources/icons/`（原型为 `prototype/assets/icons/`）；**禁止手画图标或用 Emoji/字符模拟**（影响美观且精度缺失）。
2. **无边框窗口**：主窗口禁止使用 PySide6 原生标题栏，采用无边框窗口 + 自绘标题栏（规格见 UI 设计文档 §3.3）。
3. **Mock 数据**：UI 实现阶段所有数据均为 Mock，禁止动用数据库实现（数据库属阶段三）。
